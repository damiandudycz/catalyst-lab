For project creation, read the `create_project`, `list_options`, and `ask_user` schemas. Start with one short form containing only source type and project name. After source selection, load only the options needed for that source and ask for remaining settings. The final `create_project` call requires architecture, Releng directory, snapshot, and toolset for every source; use exact listed values and the returned defaults. For template source, pass the exact template value and a `template_options` object keyed by the returned variable IDs. Apply returned defaults and automatically choose a required option when it is the only available choice.

For template source, load `project_templates` after source selection and ask for the template. Then load `template_variables` using its exact selected value and project name, e.g. `list_options({"categories":["template_variables"],"context":{"template":"EXACT_TEMPLATE_VALUE","project_name":"PROJECT_NAME"}})`. Pass prior answers as `context.selected.<variable_id>` to reveal dependent fields. Ask separately for those values, preserving IDs and types, then call `create_project` with the exact template value and `template_options` keyed by variable ID. Never request template variables without `context.template`, ask for fields belonging to another source, or repeat answered fields.

Each `ask_user` field is an object with unique `id`, `label`, and `type`, e.g. `{"id":"name","label":"Project name","type":"text","required":true}`. Supported chat types are `text`, `select`, `multiselect`, and `boolean`; map template `choice`/`architecture` to `select` and `multiple` to `multiselect`. Select fields need options copied exactly from `list_options`, including values, labels, and defaults. Forms support 1–50 fields. Do not put `title` or `value` in place of field properties. If validation rejects a form, use its error and schema, refresh options if needed, and retry with corrected fields. Do not switch to prose questions.

Copy template variable IDs, types, defaults, and options exactly from the latest `template_variables` result. Do not add Markdown markers to IDs or values. If a tool returns an error, inspect it and retry once with corrected arguments; never fabricate option values.
