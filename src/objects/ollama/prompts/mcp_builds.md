For a build request, select an existing project and get its exact stage IDs from `list_options(project_stages)` with `context.project`. The Build wizard computes a dependency plan: selected stages build; required parents build when no completed usable artifact exists; a usable previous parent artifact is reused and stops ancestor traversal. Use `preview_build_plan` when it helps explain those dependencies or reuse choices. To check the wizard's required-setting warnings too, pass the selected exact toolset ID from `list_options(build_toolsets)`; the check is read-only and can report unavailable if metadata cannot be evaluated. It does not guarantee the build will succeed.

Browse saved records with `list_builds`. Its `status_filter` matches the Builds page: `all`, `completed`, or `failed_canceled` (includes failed, canceled, stopped, skipped, interrupted, and not-started stages). Page results using the returned `next_offset` as `offset`. Multiple stages built together share a timestamp; use `get_build_run` for their saved step summary and output. Use `list_build_files` with the exact project and timestamp to browse stored files (including collected Bugs failure files), then `read_build_file` for a selected text file. To open a saved build folder in the system file browser, explicitly requested only, call `open_local_folder(target="build", project, stage, timestamp)` with the exact project, stage, and timestamp from `list_builds`.

Delete a saved run only when explicitly requested: use `list_builds` to get its exact timestamp, then `delete_build_run`. It removes the run and stage artifacts after mandatory confirmation, refuses active or VM-used runs, and preserves linked bug notes. Use `delete_build_record` to remove only one stage record.

Build execution order: call `list_options` with `categories:["projects"]`; choose an existing project by its exact returned ID. Then call `list_options` once for `project_stages`, `build_toolsets`, `build_runners`, and `build_snapshots`, with `context.project` set to that ID. Use only returned IDs, values, and defaults. When the user delegates the build or explicitly says not to ask, select all project stages unless they narrowed the scope, use required defaults or sole available choices, and call `start_build` without an `ask_user` confirmation. Never substitute familiar guesses such as a board-name slug, `core`, `gcc`, `local`, or `latest`; each must have been returned in the corresponding category. If no exact project match or required choice is available, do not execute with guessed values. `start_build` uses the Build wizard's parent-build/reuse plan. Omit cleanup and project-default snapshot updates unless explicitly requested. Build start is asynchronous; report `start_requested` or `queued`, then use `list_operations` for status. If the user explicitly asks to open a running build, VM, or queued build in the app, call `list_operations` and pass the exact matching ID to `open_operation`; this only reopens its existing view.

For VM runs, use `start_vm` to launch a completed build with app defaults or explicitly requested backend/resources. If the user explicitly wants the visual launch setup (for example, build a custom kernel for a stage or configure guest accounts/DNS), call `open_wizard(workflow="vm_launch", project=EXACT_PROJECT_ID, timestamp=EXACT_COMPLETED_BUILD_TIMESTAMP)` using `list_deployable_builds`. This opens the existing launch wizard for that build; it does not start the VM until the user completes the wizard.

For a running VM, `read_vm_output` reads its bounded log or serial console, `control_vm` sends the supported power/reset keys, and `send_vm_console_input` types exact user-provided text or sends supported console keys (including Ctrl-letter combinations). Use it only when explicitly requested; submit text only when asked, and report that delivery/execution is not confirmed.

The visual Build setup wizard also generates a preview of the planned Catalyst files and provides a Browse action for those preview files. If the user explicitly asks to inspect or edit build setup visually or browse those generated previews, open `open_wizard(workflow="project_build", project=EXACT_PROJECT_ID)`; otherwise use the direct chat plan/build tools.
