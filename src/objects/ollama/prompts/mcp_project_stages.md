Load for adding a stage or changing project-stage configuration, settings, kernels, or scripts.

For “add a stage,” load `project_stage_toolsets` with `context.project`; use its default or sole eligible toolset automatically. Load `stage_targets` with the selected toolset ID as `context.toolset`, and `project_stages` with `context.project`. Choose a sole target automatically; otherwise ask using exact options. Every target except `stage1` needs a seed parent. Load `stage_releng_templates` with `context.project` and `context.target` when the project has architecture and a Releng directory. A Releng spec is optional. Ask only for unresolved name, target, parent, or spec, then call `create_stage` with exact IDs. It creates the stage and baseline, sets the selected Catalyst toolset as the project preference, and starts an asynchronous operation; check `list_operations` for completion. It does not start a build.

For stage settings, use `get_stage_settings` to distinguish explicit, inherited, and calculated values. It reports unsupported saved values, or `support_unverified` when no toolset is available. Before selecting values, call `list_options(stage_settings)` and, for selectable values, `stage_setting_options` with `context.project`, `context.stage`, and `context.setting`. Pass exact returned values. Use `set_stage_setting` with the actual type: string for text, string array for lists/multiselect, boolean for booleans, or an array of option values for multiselect. Automatic values use `@inherit_parent`, `@inherit_releng_template`, or `@automatic` when listed. For settings combining inherited and custom values, pass both in one array. Use `reset_stage_setting` to remove an override. Use `remove_unsupported_stage_setting` only when explicitly asked to delete an exact entry from `unsupported_settings`; it requires confirmation.

To change `stage4/packages` or `livecd/packages`, inspect the current setting with `get_stage_settings` and load `stage_setting_options` using `list_options(categories=["stage_setting_options"], context={"project":"EXACT_PROJECT_ID","stage":"EXACT_STAGE_ID","setting":"stage4/packages or livecd/packages"})`. Browse the project's effective snapshot or enabled overlays with `list_repository_packages` to get exact package names and versions, then update the complete value with `set_stage_setting` as a string array. Use `category/package` for any available version or `=category/package-version::repository` for a pinned version, matching the repository name returned by the package browser. Preserve existing custom entries and selected inheritance tokens unless the user asks to replace them; do not add packages already supplied by the selected inherited sources.

For the project's preferred Catalyst toolset, load `project_toolsets` with `context.project`, then call `update_project(field="toolset")` using an exact returned ID or `default` to restore the app default. Do not use generic `toolsets` for this choice.

Use `list_stage_kernels` before kernel edits. `update_stage_kernel` supports add, rename, set/reset setting, and Releng inheritance actions. Kernel list settings take string arrays and `distkernel` takes a boolean. Removing a stage-specific kernel requires confirmation; inherited Releng kernels cannot be removed until inheritance is disabled. Load `stage-scripts` before editing a project-owned `stage4_fsscript` or `livecd_fsscript`; for script tools pass `stage4/fsscript` or `livecd/fsscript` exactly. `write_stage_script` never runs the script and asks before replacing an existing file.
